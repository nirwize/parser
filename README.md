# OLX Portugal: проверка объявлений без хранения сведений о продавце

`parser_app.py` — исходный пример для Яндекс Карт.
`olx_app.py` — новая версия для OLX.pt: окно, фоновый поток, остановка,
постраничный обход через Playwright, фильтры и просмотр подходящих товаров.
API OLX, скрытые endpoints и антидетект не используются.

## Статус проверки — 18 октября 2026

Логика проверена 29 автоматическими тестами, в том числе в настоящем Edge
на **синтетических страницах**, без запросов к OLX. Проверены фильтры,
пагинация, удаление дублей, отсутствие сведений о продавце в результатах,
обработка HTTP 403/429, CAPTCHA и закрытие контекста браузера.

**Работа на живых карточках OLX пока не подтверждена.** Проверка публичной
страницы через обычный Edge на этом компьютере получила HTTP 403.
Парсер остановился. Защита не обходилась.

Публичные ссылки категорий, ссылки вида `/d/anuncio/…-ID….html`, надпись
`Seguinte` и формат регистрации `No OLX desde …` проверены по публичным
страницам через веб-поиск. CSS-селекторы полей карточки в `config.json`
являются **кандидатами**, проверенными только на тестовых страницах.
Для рабочего запуска их ещё нужно сверить с доступной разметкой OLX.
Отсутствующий элемент приводит к пропуску; это не означает, что у продавца
в действительности нет нужного признака.

Источники:

- https://www.olx.pt/ — каталог разделов.
- https://www.olx.pt/tecnologia-e-informatica/ — выдача, объявления и пагинация.
- https://www.olx.pt/moveis-casa-e-jardim/ — разделы мебели и бытовой техники.
- https://developer.olx.pt/api/doc?_locale=en — Partner API; в этой реализации не используется.
- https://playwright.dev/python/docs/locators — работа с элементами браузера.

## Запуск на Windows

В этой папке уже создано `.venv` и установлен Playwright 1.64.0.
Можно запустить `start_olx.bat` двойным щелчком или выполнить:

```powershell
.\.venv\Scripts\python.exe olx_app.py
```

Для установки на другом компьютере:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Нужен установленный Chrome или Edge. Если их нет:

```powershell
.\.venv\Scripts\python.exe -m playwright install chromium
```

Проверка настроек и консольный запуск:

```powershell
.\.venv\Scripts\python.exe olx_app.py --check-config
.\.venv\Scripts\python.exe olx_app.py --cli --target 10 --max-ads 100
```

По умолчанию результаты остаются только в окне или выводятся в консоль.
Двойной щелчок в таблице открывает объявление. Кнопка «Сохранить результаты…»
сохраняет только поля товара в JSON по явному действию пользователя.
CLI может сохранить новый JSONL-файл через `--output filename.jsonl`;
существующий файл не перезаписывается.

## Проверки

Объявление показывается только после всех успешных проверок:

1. Публичная ссылка `https://www.olx.pt/d/anuncio/…`.
2. Непустой заголовок и явно указанная числовая цена в евро.
   «Troca», «Sob Orçamento» и отсутствие цены не принимаются.
3. Метка `Particular` в параметрах именно этой карточки.
   Метки `Profissional`/`Empresa`, противоречия и явные коммерческие фразы
   приводят к исключению.
4. Подпись `No OLX desde …` в блоке продавца целиком попадает в период
   с 01.01.2025 по 31.12.2026. Дата публикации и время последнего посещения
   не подменяют дату регистрации. Если указан только месяц, проверяется
   весь месяц, а не выдуманное число. Будущая регистрация отклоняется.
5. В публичном блоке контакта/продавца уже видна действующая ссылка `tel:`
   на португальский номер. Программа получает только логический результат
   проверки и **не возвращает номер из браузера**.
6. Категория текущей карточки подтверждена хлебными крошками или публичной
   разметкой BreadcrumbList и соответствует выбранному разделу.
7. Доступно описание, и нет настроенных признаков недвижимости, транспорта,
   услуг, вакансий, цифровых товаров или коммерческого предложения.

**Кнопки «Mostrar número» или «Позвонить» недостаточно для подтверждения.**
Программа не нажимает их, не раскрывает номера и не входит в аккаунт.
Если телефон скрыт за кнопкой/авторизацией, запись пропускается с причиной
«наличие телефона не подтверждено». Поэтому строгая проверка может дать
очень мало результатов или ни одного. Страницы профилей отдельно не обходятся:
используются сведения в блоке продавца на странице объявления.

Статус `Particular` является заявлением на сайте. По открытой карточке нельзя
гарантированно выявить профессионала, который выдаёт себя за частное лицо,
или товар, ошибочно помещённый в категорию. Дополнительные исключения по тексту
сделаны консервативно и могут отклонять допустимые товары (например, вещь
с упоминанием ремонта). Они настраиваются; это не безошибочная классификация.

## Какие данные остаются

Единственная модель результата содержит:

```json
{
  "title": "Monitor",
  "price_eur": "120.00",
  "category": "Электроника",
  "url": "https://www.olx.pt/d/anuncio/example-IDexample.html"
}
```

Это вымышленный пример формата, а не найденное объявление.

Имена, ссылки/ID профилей, даты регистрации, номера телефонов и флаги продавца
не входят в результаты, экспорт или логи. Регистрационная подпись используется
только временно в памяти. Номер не передаётся из браузера в Python.
Описание служит только для проверки исключений и не возвращается из браузера.
Явные португальские номера и email в заголовке маскируются; ссылки объявлений,
в чьём адресе найден такой контакт, отклоняются.

Не создаются HTML-дампы, скриншоты, HAR, трассировки, файлы сессий или база
продавцов. Используется новый непостоянный браузерный контекст. Дедупликация
работает по ID объявления только в памяти одного запуска.

## Настройки

`config.json` перечитывается при каждом запуске поиска из окна.

- `categories`: название, публичный URL, `enabled` для каждого раздела.
- `registered_from`, `registered_to`: включительные границы периода.
- `target`: сколько подходящих объявлений нужно.
- `max_ads_per_run`, `max_pages_per_category`: ограничение объёма проверки.
- `delay_seconds`: пауза между переходами, минимум 2 секунды.
- `timeout_seconds`, `max_retries`: таймаут и ограниченные повторы.
- `browser_channel`: `auto` выбирает семейство браузера, назначенного в Windows для HTTPS; `chrome`, `msedge` или `chromium` задают браузер явно. Для Firefox используется совместимая сборка Playwright (`python -m playwright install firefox`), а не обычный профиль Firefox.
- `headless`: показывать или скрывать окно браузера.
- `blocked_category_terms`: исключённые ветки категорий.
- `excluded_offer_patterns`, `business_patterns`: регулярные выражения для
  текста на португальском, приведённого к нижнему регистру без диакритики.
  Используйте синтаксис, совместимый с JavaScript и Python.
- `selectors`: CSS-селекторы выдачи и конкретных полей карточки.

Нельзя заменять отсутствующий блок продавца всей страницей: это может принять
дату, телефон или тип продавца из рекомендации/рекламы/подвала за данные объявления.
Если OLX меняет разметку, нужны узкие селекторы соответствующих блоков.

При HTTP 401/403, CAPTCHA или входе в аккаунт сбор прекращается. При HTTP 429
учитывается `Retry-After`; длительное ожидание или исчерпание повторов завершает
запуск с явным сообщением. Ошибки соединения и 5xx имеют ограниченные повторы.
«Стоп» прерывает ожидания; уже начатая навигация может ждать до заданного таймаута.

## Структура

- `olx_app.py` — окно и CLI.
- `olx_parser/core.py` — настройки, URL, цены, даты, фильтры, модель товара.
- `olx_parser/browser.py` — Playwright, пагинация, задержки, ошибки, остановка.
- `olx_parser/extract.js` — чтение публичных полей DOM без сетевых вызовов.
- `tests/` — правила и браузерные проверки с синтетическими страницами.

Проверка:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -v
```

не добавлен; callback `Scanner(..., on_result=...)` получает только модель товара
и может использоваться для следующего этапа интеграции с ботом.
